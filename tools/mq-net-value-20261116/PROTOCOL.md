# RocketMQ 净收益最小预实验（2026-11-16）

目标是结束收益争议；只描述本机小样本，不估计稳定 P95、生产容量或 MQ 相对简单异步的优势。

- 精确资源：既有 `ai-interview-m1c-mysql-a-1` / `mysql-b-1`，127.0.0.1:3317/3318 的 `ai_interview_test`；同项目专用 namesrv/broker（19876/20911）。已核验标签、镜像、独立卷、相同 MySQL 1 CPU/768 MiB 配额。只 start/stop 原容器，不重建、不迁移、不清理旧数据。其他 local/evaluation/其他项目资源不参与实验。
- A：历史同步 JAR `3fb095291adf7b21e8b69695f70aaa6085e6631b29522583f21af11a2e0d7c52`。B：当前候选 `0509cd6` 的独立构建 JAR `3346146f49fca7c7c604b2d70c3ebddc134d7d49a97467a07d80fe35c2fa07e0`，4 消费线程/500 ms/提交后唤醒。各轮仅启动一侧应用，同 Java 21、128/512 MiB 堆、Hikari 10/10、Tomcat 默认配置。记录实际资源，无进程 CPU 隔离；相同宿主上仍有其他服务。
- 唯一新 Topic/group `ai-interview-netvalue-20261116` / `ai-interview-netvalue-20261116-consumer`，1 读/写队列。保留消息和偏移。完整模型请求强制到 loopback 替身；无外部 API、无真实凭据。
- 共同模型桩显式 `Semaphore(4)`；取得许可后固定等待 1 秒，再返回同一合法报告。分别记录到达、许可、服务结束、完整请求 JSON 规范化 SHA256 和实际峰值。不得用应用在途数代替桩服务并发。
- 客户端闭环并发 1、4、8；每侧每层 8 测量＋2 预热，顺序 AB、BA、AB，总计最多 48 测量＋12 预热。每个并发层只有一轮；不扩样以追求显著性。任何业务失败、请求配对失败、模型越界、隔离失败均停止并保留结果。
- 每请求 5 MAIN、5 FINAL、无追问、同内容/分数/弱项键分布，独立合成用户；A/B 每对完整模型请求必须相同。不修改 Prompt、业务校验、事务或 ACK。只插入新前缀夹具；不覆盖/删除历史行。
- 背景已知不等：A/B 历史 Session 为 1273/1514、无 GENERATING，B 无 QUEUED/RUNNING；因此是控制模型上限、资源配额和输入的有限对照，不是背景数据完全相同的严格实验。不得用填充或删库掩盖差异；若需严格同背景，需要另行批准新副本，当前收口不要求。
- 同 JVM 单调时钟：T0=服务端 POST 入口；T9=报告最终事务 afterCommit；B 另有 T1=受理 afterCommit、T2=领取派发、T7/T8=模型客户端调用。复用已有只观测的 R2 探针，不把 updated_at 当提交时间。客户端单调时钟独立记录 HTTP 返回和 200 ms GET 观察 READY；浏览器首次内容/完整 DOM 时间不在此实验，引用历史浏览器证据。
- 完成吞吐=本轮成功数/客户端整轮时间（含起步与排空）；另报 DB 完成速率。逐样本均值、中位数、范围；不报新 P95。保留全部预热、失败、资源采样、源文件散列、结束数据库对账。
- 结束仅停止本轮应用和四个原来停止的专用容器，保留数据库、消息、卷。正常关闭优先用镜像 `mqshutdown`；不以强制退出伪装优雅关闭。
