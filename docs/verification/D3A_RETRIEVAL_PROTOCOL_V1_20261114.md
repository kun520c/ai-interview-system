# D3-A 独立检索评测规程 v1

日期 2026-11-14（Asia/Shanghai）。查询文本、指标及标注准则已冻结，真实检索未执行。语料定稿后，在首次真实入库前离线生成并冻结 Chunk 真值。开发调试使用独立样本。

## 1. 查询与隔离

[冻结查询 JSON](D3A_RETRIEVAL_QUERIES_V1_20261114.json) 包含 60 条。Q01–Q12 为同义场景，Q13–Q24 为口语或不完整表述，Q25–Q36 为跨主题，Q37–Q48 为相近机制辨析，Q49–Q60 为无充分依据。正例预期 48 条，负例预期 12 条，涵盖九个题库领域。每条记录保留用户式查询、领域、证据意图与主题导航。只有 query 字段送入检索。主题导航帮助标注员查找材料，任何其他有直接证据的 Chunk 同样可被判为相关。

查询通过 NFKC、大小写和标点空白归一化后的逐条查重，和 63 条题干、63 份参考答案及 298 条评分点的精确重复为 0。已逐类人工初审，调整近重复例和负例口径。选题来自公开技术主题和场景设计，仍共享技术概念。人工复核需关注同一叙述顺序、同一数据、简单换词或复用题库反例。入库前保留复核回执。查询文件在仓库内可见，文档作者以目录和来源卡为输入，评测负责人管理查询和真值。对能看全仓库的参与者无法保证访问隔离，正式泛化结论需由独立评测员再密封一组同分布新查询。v1 作为预注册验收集，其已知查询及结果不得用于本批内容择优。查出具体技术错误时按来源修复，发布新语料版本，并用新留出集复验。若需修改已冻结的查询或指标，另起版本，保留旧文件与原因。

固定参数记录包括查询字节摘要、语料文件摘要、切片器源码摘要、Chunk 规范化 UTF-8 SHA-256、JDK、Embedding 模型与 profile、维度、COSINE、索引与搜索参数、阈值是否开启及绑定值、提交源码和配置摘要。候选集合与已存在 E01 的映射要在同一 manifest 上声明。阈值保持当前默认关闭，0.70 为关闭状态下的缺省参数。各候选版本需要先登记，禁止查看 v1 输出后挑阈值或重排参数。

生产的 MAIN 查询由主问题和全部评分点构成，FOLLOW_UP 由主问题、追问和目标评分点构成，两者均排除答文。生产路径检查可以另建回放集，独立检索使用冻结的新查询直接调用检索层，禁止把题库原文拼回独立输入。最终证据由真实 `EvaluationPromptBuilder` 在内存构建，用合成最小上下文提取 `RAG EVIDENCE` 的精确列表，保留原始排名和 ID。评测不调用评分模型、不推进业务状态、不调用生产编排写追踪表。

## 2. 人工真值

离线使用实际 `KnowledgeTextChunker` 得到最终文本，稳定身份为 `文档计划ID/内容版本/切片序号/切片SHA256`。每条冻结查询对所有冻结 Chunk 做成对标注。预计约百余 Chunk 时采用全量标注，实际工作量为 `60 × N`，由 dry-run 决定 N。两位标注员各自审核打乱顺序的纯文本和必要来源/版本，均看不到模型排序、相似度或对方标注。第三人处理分歧。若后续大幅扩容需采样，先发布新协议，不以检索 Top5 自身形成当前版本真值。TREC 的 relevance judgments 可用于核对标注实践，本项目选择全量离线标注以覆盖无命中和相邻误召回。 [NIST TREC 相关性判断](https://trec.nist.gov/data/reljudge_eng.html)

- **DIRECT**。Chunk 含可独立引用的正确机制，能直接支持查询中的至少一个实质意图。标注需给最短有效原文位置、适用版本、意图子项及缺失条件。跨主题可由多个 DIRECT 分别支持子项。Q25–Q36 的 requiredIntents 提供稳定子项 ID，fullAnswerRequires 冻结完整回答所需的子项组合。
- **RELATED_ONLY**。话题相邻，但缺少对意图有用的机制、关键条件或上下文。仅有标题、同词、引用列表、半段内容或泛泛背景，均不记有效证据。
- **IRRELEVANT**。内容不支持意图，或版本、系统前提不兼容。明确错误、误导或提示注入另记 `harmful=true`，必须附理由。
- **UNCERTAIN**。证据边界有争议或事实待核对，保留双方判断和理由。发布冻结真值前裁决为前三类，未裁决不得进入验收计算。

标注字段至少包括 `queryId, chunkKey, assessorId, label, supportedIntentIds, spanStartUtf16, spanEndUtf16, versionCondition, reason, harmful, adjudicator, finalLabel`。原文偏移以零起点 UTF-16 code unit，结束位置排除。每对唯一保留两份原始判断及一份最终判断。supportedIntentIds 为多值集合。报告三类混淆矩阵、原始一致率、Cohen κ、分歧数、裁决依据及待决数。用少量非冻结示例校准标签，正负预期以冻结查询为准。预期正例经全量标注后无 DIRECT 时登记为语料缺口，保留在 48 条分母并记 miss。预期负例若有 DIRECT，记录查询设计与真值冲突及原始判断，保留原分组并中止本版本质量判定。更改预期须另起版本。直接反驳错误前提的证据可以是 DIRECT，描述所需观测的材料不能支撑查询索要的实例事实。冻结回执包含标注结果、评测规程、查询集、最终语料和 Chunk 清单的 SHA-256。标注员与裁决人的签字、时间及样本数纳入回执。

## 3. 指标和记录方式

记录三阶段证据集合及顺序。A 为 Milvus 原始 Top5。B 为阈值与 MySQL 资格过滤后的候选，保留 Milvus rank，不补位或重排。C 为实际 Prompt 证据。当前适配器把检索通过的全部 evidence 交给 PromptBuilder，后者逐条输出。Top5 可能只剩部分或全部空，来源包括少量命中、可选阈值或 MySQL 过滤。当前源码无额外 Prompt 条数上限；未来若有正文裁剪或去重，以最终序列化内容重判 C。仅凭 Chunk 原文相关不能证明裁剪后的 C 仍有证据。

- **Hit@1/3/5**。每条查询在原始 rank ≤ k 中有任一 DIRECT 记 1，其他记 0。A、B 分别算。B 原 rank 1 被过滤时，原 rank 2 保持 2。C 用原 rank 计算保留后的命中，也列最终展示序号作诊断。
- **Precision@5**。原始 rank 1–5 中的 DIRECT 个数除以 5，少于 5 条的空位计 0。A、B 分别算。各阶段按 chunkKey 只给首次出现的位置记 DIRECT，重复项和同文档占位另计为诊断。同文档内不同 Chunk 独立计分。
- **MRR@5**。首个有效证据的原始 rank 为 r，r ≤ 5 时取 1/r，无有效证据取 0，按查询平均。同步给首条有效证据排名直方图 1/2/3/4/5/未命中和正例命中数。
- **最终 Prompt 证据相关率**。C 中实际呈现为 DIRECT 的条目数除以 C 实际呈现的条目数，跨查询汇总。分母 0 时记 N/A，并报分母、空 Prompt 率及正例含 DIRECT 的查询比例。重复证据最多计首条有效，剩余保留在分母。
- **负例与错配**。单列 12 个预期无 DIRECT 样本的非空 Prompt 率、每个误纳条目的 RELATED_ONLY/IRRELEVANT 数、含有害证据的查询数。负例没有 DIRECT 本身不表示已可靠拒绝。记录 A→B→C 的每条过滤/保留理由及原 rank。跨主题按阶段计算已支持的 distinct 子项数 / 固定 requiredIntents 数，并报满足 fullAnswerRequires 的查询数 / 12。
- **失败与分母**。正例 48 条为主分母，另外报告 60 条全样本口径和按领域、查询类型的小样本绝对计数。运行失败单列。正式质量判定要求 60/60 有有效运行结果，报告另附将失败视为 miss 的端到端值。任何返回的 Chunk 身份不在冻结 manifest 或无法人工标注时，中止该版本判定。摘要保留原始分数、耗时及同分顺序，禁止择优重跑。

固定计算示例。原始第 1 条为 DIRECT 但资格过滤，第 2 条为 RELATED_ONLY，第 4 条为 DIRECT，其余为空或不相关。A 的 Hit@1/3/5 均为 1，Precision@5=2/5，RR=1。B 的 Hit@1=0、Hit@3=0、Hit@5=1，Precision@5=1/5，RR=1/4。若 C 仅含第 2、4 条，Prompt 相关率为 1/2。

## 4. 首次判定与留出保护

入库前硬门禁为技术内容、来源、版本与完整性审查，且标注冻结。真实入库后，首次独立评测固定运行一次，技术执行门禁要求 60/60、未知 Chunk 为 0、有害 Prompt 证据为 0。第一版建议业务门槛为 B Hit@5 ≥ 43/48、B Hit@1 ≥ 34/48、B MRR@5 ≥ 0.75、C 正例含 DIRECT ≥ 43/48、C 证据相关率 ≥ 0.65。以上为本轮预注册的初验提议，源于拟议质量容忍度，尚无 D3 运行数据。业务负责人如需不同门槛，首次真实检索前记录批准版本，历史 21 题数据不用于推导新阈值。Hit@3、Precision@5、负例非空率和意图子项覆盖先完整报告。负例即使误纳背景材料，也不能由简单的余弦阈值自动推断事实可靠性。

结果只用于发布判定和错误归因。评测负责人先按缺资料、切片丢上下文、向量召回、资格过滤、Prompt 处理或标注争议分类，定位后用独立开发样本修复。指标未达门槛时保留原始结果，下一版冻结新留出查询及真值。既有 4D5 回放可用于兼容性验证，不能用历史高命中推断 v1 的泛化结果。
