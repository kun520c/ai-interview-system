# S1｜面试题目可见性与 Git 安全审查

日期：2026-11-14（Asia/Shanghai）。审查对象是仓库当前候选人接口及 U2 恢复链路；本报告不包含真实用户题答、凭据或受保护 evaluation 行。

## 发现与修复

- **P1：本场未来主问题提前暴露。** 修复前的真实 HTTP 合成场景中，创建 EASY 面试后，`GET /api/interviews/{sessionId}` 返回 5 道主问题，包括 4 道 `PENDING` 题目的题干、题号、分类、知识点、顺序及状态。拥有自己会话的普通用户可以直接请求详情取得题目，不依赖前端显示。此问题影响面试题目保密性，未证明可访问其他用户会话。
- 同一修复前请求及当前题请求中，测试未发现参考答案、评分点、权重、内部评分结果或原始模型结果。对应响应 VO 也不包含快照字段；这不是对所有未知接口的普遍保证。
- JWT 由服务端验证签名和有效性，过滤器从数据库重新读取用户；详情先校验会话归属，非所属用户返回 404。实测未认证 401、篡改令牌 401、跨用户详情 404、普通用户访问管理接口 403。
- 根因是详情把完整持久化计划直接映射为响应。`InterviewService.getDetail` 现在仅选择当前题或状态为 `ANSWERED` 的题目；非当前题还必须具有真实提交记录。`PENDING` 和没有提交记录的非当前题不返回。历史答案即使尚无评价也可查看；评分反馈仅来自已保存评价。
- 不修改随机组卷、快照、状态机、评分、RAG、数据库结构或外部服务。U2 使用的当前题及已评价历史保持可见；并发时若当前题恰好变化，前端现有一致性检查会拒绝旧结果并提示重试。
