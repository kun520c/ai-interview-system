# 评分质量的离线评测协议 v1

适用对象是固定题目快照、已冻结回答和既有生产评分链。它是本轮的工程可行性协议，门槛尚未由足够的独立人工案例校准，**不能直接作为全题库正式质量验收标准**。

## 1. 评价单位和标签

逐个记录回答、题号及评分点 ID、评分点完整原文/类型/权重、主答或追答模式、输入证据版本和人工依据。题干要求但没有独立评分点承载的内容（例如题 24 的名称）另记为题目级要求，不凭空分配到已有评分点。

离线标签为 `COVERED`、`PARTIAL`、`MISSING`、`INCORRECT`、`UNCERTAIN`；独立记录审核状态 `HUMAN_CONFIRMED`、`HUMAN_REVIEW_PENDING`、`AI_DRAFT`、`UNCERTAIN`。同一评分点可能有正确子项、错误子项和缺项，应记录原句及各自依据。遇到 ALL/ANY、例子或不同实现范围不明，先标待裁决；**PARTIAL 永不自动映射生产 Boolean**。AI 对模型文字的复核也标为候选，直至人工确认。

## 2. 主指标：评分点与事实

以人工明确的二元点为分母，按题目与点 ID 对齐：

- 金标 COVERED 且输出 true：正确覆盖被认可；COVERED 但 false：错误判漏。
- 金标 MISSING 且输出 false：真实缺失被识别；MISSING 但 true：真实缺失被漏报/错误认可。
- PARTIAL、INCORRECT 或 UNCERTAIN 不机械加入以上分母。事实错误另以“错误事实 × 回答”记录原句、技术依据及模型是否纠正；输出文本是否真的纠正也需人工审核。
- `missingPoints`、`correction`、`strengths` 分开核对：是否把已答列缺失、遗漏真实缺项、将拓展当必答、把不存在的错误归给回答；布尔正确不自动代表文字正确。
- 特别标识等价表达、复合点局部正确、互相矛盾及不可裁决案例；分别报告分子/分母及案例。单次模型调用的重复结果可用于稳定性，但不能冒充相互独立的样本。

## 3. 辅助指标：分数区间

Java 五维各 0～20 的整数，总分取五项之和；评分点 weight 不用于生成总分。只有人工事先给出有理由的区间，才计算“区间内的有效回答数 / 有区间且有合法输出的回答数”，并记录超出距离；无可信区间则分母为零、指标未定义。不使用统一误差带。重复输入报告各维和总分极差；经过人工确认的整题等价回答可成对比较总分，否则只比较相同的评分点。错误事实获得的分数是否过高需要独立的分数锚点，不能只因数值大就宣称不合格。

## 4. 辅助指标：结构、依据与追问

逐次记录 HTTP 状态、原始内容 JSON 语法、生产 Client 解析、Java Validator、缺失/重复/陌生评分点 ID、五维和、finish reason 与耗时；其中任何前一层失败应保留原始响应并区分后续层未执行。

逐点评审 evidence 是否有主答/追答原文支持、被引用位置是否准确，不能把 RAG 证据冒充答题证据。字面子串检查只可辅助定位，既不能自动证明事实正确，也不能把正确的改写一概判错。追问分别记录模型建议、理由、Java 最终决策与目标，核对目标是否是真正缺口、是否触及非必答拓展；FOLLOW_UP 不应再次追问。

## 5. 数据、执行和归因

按题目分组冻结开发集和留出集；留出集按文件 SHA-256 固定，候选模型/规则未经冻结不得用留出结果调参。对人工裁决尚不足的样本只做探索，不纳入正式质量率。每一轮保留数据/Prompt/代码哈希、RAG 证据来源和当时条件，明确实时检索还是历史证据。先少量探针，再依据实际余额、可得用量和上限执行；尝试在发起前记账，遇到响应/usage 未知时停止而不自动重发。

失败按证据分别归类：题干歧义、标准/权重或必答范围不清、参考答案问题、人工判断分歧、模型语义或事实错误、RAG 不足/干扰、结构违约、Java 业务约束或校验缺陷。无法排除多种原因时保持未定；没有对照不能推断因果。候选修复必须以独立已人工复核的留出集检查误认、判漏、追问、事实与结构的双向变化。
