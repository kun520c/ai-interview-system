# 保留的失败和边界

1. **本轮、调用前计划比较失败。** 第一次 `execute probe` 由于 Jackson 内存中 `LongNode` 与解析后的 `IntNode` 比较不相等，触发 `FROZEN_PLAN_MISMATCH`。该门禁位于写 `started.json` 和任何 HTTP 请求之前；随后查证 `started.json` 不存在、请求文件 0、usage 日志不存在。修正为序列化再解析后比较，原两阶段冻结计划不重建、不覆盖；之后实际发送探针 2 次和基线 10 次。
2. **本轮、运行库数量未核实。** 自动审批拒绝从现有运行进程环境提取凭据并访问正式 local 库，理由为用户未明确授权这种非标准凭据获取方式，存在凭据暴露风险。被拒动作未执行；相关尝试性离线代码已移除，未绕过审批。evaluation 专用账号的只读 63 题结果不能代替 local 当前题数。
3. **历史 Q2 v5 失败。** 原有已揭盲旧样本上 18 HTTP 200、17 次解析和 Java 校验通过、1 次 JSON 解析失败，且出现语义退化，候选撤回；见 [Q2 原报告](../q2-20261114/DIAGNOSTIC.md)。不能将其结果当本轮 v4 或独立留出测试。
4. **历史 Q2-R2 未知尝试。** 原记录 1 次发起但没有响应、usage 或可核账的供应商请求 ID；无法判断是否到达或计费，也未完成旧新对照。此次没有重发该历史请求，保留 [原记录](../q2-20261114/q2-r2/COMPARISON_SUMMARY.md)。
5. **本轮无意义的指标不补数。** 没有人工总分区间、已确认整题语义等价配对及独立人工留出，因此相应命中率、改写分差和总体准确率未定义。未将结构通过或 AI 技术复核冒充人工验收。
6. **追答目标来源修正。** 开发集 v1 对两张历史追答盲卡写了空目标数组，但盲卡没有记录目标 ID；空数组不能证明当时目标为空。新增 v2 将这两处标为未知，保留已冻结的 v1 和原哈希；两张追答均未进入本轮真实调用，12 个实际请求不受影响。以后须从可信历史快照确认目标后再构造 FOLLOW_UP 请求。

[未采用的评分与报告 Prompt 改动摘录](FAILED_PROMPTS.md)仅保留通用系统指令和失败边界，原始作答及响应仍为本机私有材料。
