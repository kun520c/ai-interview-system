# 对象相等、哈希契约和稳定键

适用 Java SE 21 Object 与常用哈希集合契约。桶路径以 OpenJDK jdk-21+35 为例。

## 逻辑相等和哈希约束

Object 的默认 equals 按引用身份判断。业务值如仓库货位可用不可变的仓库 ID 与货架编号定义相等，并满足自反、对称、传递和条件不变时一致，对非 null 实例与 null 比较返回 false。equals 为真时，两个对象在同一次执行中必须具有相同 hashCode。相同 hashCode 可能发生碰撞，不能证明对象相等；跨进程稳定散列也需要独立合同。

## 哈希容器中的定位与候选比较

以 OpenJDK 21 HashMap 为例，getNode 先根据键 hashCode 的扰动结果定位桶，在候选中比较保存的散列，再按引用相同或 equals 判定目标。HashSet 使用 HashMap 支撑成员管理。只重写 equals 时，两个逻辑相等实例可能得到不同哈希，表现为第二个实例查询不到条目或去重失效。即使一次查询偶然成功也不能证明契约成立。仅用 hashCode 代替最终键相等判断则可能将碰撞的两个业务实体误合并。

## 键的生命周期

用可编辑的显示名参与 hashCode 时，已放入 Map 的键改名可能使后续查找选错桶，也可能破坏 Set 的成员语义。用稳定 ID 或不可变值对象做键，把显示名作为值。测试至少覆盖不同实例但业务字段相同、业务字段不同但刻意碰撞、尝试更改输入对象后持有的键不变三种情况。跨数据库或网络编码时另用显式标识。
