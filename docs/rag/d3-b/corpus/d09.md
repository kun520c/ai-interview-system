# Redis 经典数据类型与命令选择

## 整值、计数和字段

以 Redis OSS 7.2 为参考，值类型决定可以对一个 key 执行哪些操作。String 可以保存序列化配置、原始字节或整数文本，符合整数格式和范围的值可以用 INCR 原子加一。如果每次都读写整个设置对象，序列化 String 容易维护。若要独立更新主题颜色、语言等字段，Hash 提供 `HSET settings:42 theme dark` 和 `HGET settings:42 theme` 这样的按字段读写。键级过期仍作用于整个 Hash。Redis 7.2 不提供后来版本加入的 Hash 字段级过期命令，设计时应按实际版本选择。

## 双端序列和去重集合

Redis List 保留元素位置并允许重复，从同一端入和出可以形成栈，头部 LPUSH 加尾部 RPOP 可形成简单 FIFO。例如分别 LPUSH 任务 a、b，则下一次 RPOP 先返回 a。pop 会移除元素，消费者取出后崩溃不会自动恢复该任务，可靠处理还需确认和恢复设计。Set 维护无序唯一成员，用 `SADD visitors:day u7` 记录访客，再次加入同一用户仍只有一个成员。可用 SISMEMBER 查成员，用 SINTER、SUNION、SDIFF 表达交集、并集、差集。依赖成员迭代顺序实现排队会得到错误语义。

## 排序集合与范围访问

Sorted Set 的成员唯一，成员各有 score，支持按分数或排名范围读取。给两个选手相同积分并不会合并成员，同分时按成员字节字典序排列，逆序查询的顺序相应反转。再次 `ZADD` 同一个选手会修改其分数。积分榜或按到期时间取候选项可以采用 Sorted Set。若业务需要同分按到达时间排，就要显式编码并验证这一规则，或者单独保存必要字段。String、Hash、List、Set 与 Sorted Set 是五种经典类型，Redis 还提供其他类型，是否需要用取决于访问方式和故障合同。

## 可观察的选型对照

在本地测试实例分别用两次 LPUSH、SADD、ZADD 写入相同标识，再读 List 长度、Set 基数和 Sorted Set 的分数。你会分别观察到序列保留重复、Set 去重、Sorted Set 的同一成员被更新。先描述数据约束和读写方式，再选择 Redis 类型，避免用集合遍历代替成员查询或把短暂的 List 当作有确认机制的消息系统。
