# OpenJDK 8u ConcurrentHashMap 的桶协调

实现范围固定 OpenJDK jdk8u402-b06。公开单键更新与迭代语义另见并发集合契约。

## 表、空桶和非空桶写入

8u 的 ConcurrentHashMap 以 table 和链表或树桶承载映射，Segment 类型及字段主要服务于历史序列化兼容。普通 putVal 发现表槽为空时用 CAS 把新节点从 null 原子替换进去，不需要进入桶头监视器；竞争失败就重试。遇到普通非空桶，写入线程在看到的桶头 f 上 synchronized，取到锁后再次确认表槽仍指向 f，随后修改链或树。其他桶通常可以并行操作，树桶还有自身的读写协调。

## 普通读取路径

get 读取可见的表槽，并通过 Node 的 final 或 volatile 字段读取 hash、key、value 和 next 等必要信息。普通链表读取不走写入者的 synchronized(f) 路径。转发表和树桶有专门的 find 路径，树桶可协调树读或退回链表查找。由此不能推出任意复合读写无竞态，例如 get 后按旧值 put 仍可能丢更新。

## 扩容期间的协作

扩容将桶迁到新表，旧表相应位置放入 ForwardingNode，用 MOVED 标记表示需沿下一张表访问。普通 get 遇到迁移节点可跟踪到新表；写入者遇到迁移节点，在满足条件时通过 helpTransfer 参与分段搬运，再沿新表重试。迁移协作减轻单个线程承担全部桶的成本。排查热点键写入时仍应检查同一桶或同一映射上的竞争，不能只依据结构称它完全无锁。
