# Spring Bean 作用域与请求状态

适用 Spring Framework 6.2.19、Servlet MVC 的 Web-aware ApplicationContext。作用域控制容器按什么单位选择目标 Bean 实例。默认 `singleton` 在一个容器里按 Bean 定义共享同一实例。同一个 Java 类注册为两个 Bean 定义，可以有两个单例。另一个容器也可以有自己的实例。`prototype` 每次向容器获取时创建新目标，包括创建某个消费者时的一次依赖解析。将 prototype 直接注入单例后，该单例字段保存当次得到的引用，后续普通业务调用继续使用同一对象。确实需要每次新建时，可以在调用点使用 `ObjectProvider<T>.getObject()`，并按需负责短生命周期对象的清理。

## 以 HTTP 请求作为实例边界

`request` 作用域要求活跃的 Web 请求。同一 HTTP 请求内解析同一请求作用域 Bean 会复用该目标，不同请求各有自己的目标。长生命周期单例需要使用短生命周期组件时，可以注入作用域代理，在调用时解析当前请求目标，也可显式按需查找。在脱离请求上下文的异步任务里，优先在提交任务前提取必要数据并以参数传入。作用域规定的是实例身份与查找时机，共享对象仍需依照 Java 并发规则设计。

## 识别请求身份串用

假设默认单例 `OrderService` 把当前用户 ID 写到字段 `currentUserId`。请求 A 写入 42 后挂起，请求 B 将字段改为 73，A 恢复后可能用 73 查询。即使字段改成 `volatile`，两次访问之间仍可发生 B 的覆盖，整个请求不会获得自己的字段副本。可让授权过滤器解析身份，把 `userId` 作为 Service 参数保存到局部变量。只有多组件确实需要共享请求内状态时，才引入正确作用域的组件。用两个带不同合成身份的并发请求并控制交错顺序，可核对每个响应的资源归属。
