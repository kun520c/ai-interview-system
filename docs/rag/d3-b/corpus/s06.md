# Spring 声明式事务的边界与回滚诊断

适用 Spring Framework 6.2.19 命令式事务、一个 JDBC 数据源和 MySQL 8.0 InnoDB。调用受管 Bean 的事务方法时，代理在匹配的入口选择事务管理器，创建或参与事务，并让支持 Spring 事务的 JDBC 数据访问使用绑定的连接。目标对象内部以 `this` 调用事务方法会绕过代理，内层事务声明得不到单独处理。多个管理器并存时要核对注解选择的管理器与 Mapper 使用的数据源。分离事务 Service 后，由调用方通过代理进入，也可以使用 `TransactionTemplate` 显式划定范围。

## 默认回滚与 rollback-only

通常 `RuntimeException` 和 `Error` 穿出事务方法时默认回滚，受检异常默认不触发回滚。可用 `rollbackFor` 为业务异常显式设规则，Spring 6.2 也支持调整全局默认回滚策略。事务方法内部捕获异常并正常返回，拦截器可能按正常完成路径处理。但已参与事务的内层方法若标记了共享事务 rollback-only，外层捕获后无法解除，最终提交可抛出 `UnexpectedRollbackException`。应用要根据完整业务不变量决定传播异常、显式标记回滚或隔离可选工作。SQL 更新零行也可能是业务失败，应验证预期行数并在需要时主动报错。

## 以同库工作单元验证边界

例如订阅创建必须同时写主记录和配额流水，把两次更新放在同一短事务。让第二步确定性失败，通过另一条连接检查两处是否都未提交。把失败替换为穿出代理的受检异常，分别验证默认规则和显式 `rollbackFor`。远程调用产生的副作用超出 JDBC 本地事务边界，长调用还会延长数据库持锁时间。若提交后需要通知另一系统，可先在业务事务持久化待办，再用有界恢复发送。
