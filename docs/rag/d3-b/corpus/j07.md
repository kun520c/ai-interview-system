# 反射成员发现与 JPMS 访问控制

适用 Java SE 21 的具名模块，以下以跨模块读取普通 private 实例字段为例。

## 成员元数据与执行权限

宿主通过 PluginConfig.class.getDeclaredField("token") 能发现 PluginConfig 自己声明的字段，包括 private 字段；它不向父类搜索。Field 对象保存元数据。随后 Field.get(config) 默认仍检查当前调用者访问权限，没有权限会抛 IllegalAccessException。对已有实例可用 field.canAccess(config) 判断当前调用者能否访问；成员查找成功不能证明该结果为 true。

## 导出和开放的边界

exports config.internal 使其他读取该模块的模块能使用包的 public API；跨具名模块读取普通 private 字段还需要该包向调用者开放。假设字段所在包仅 exports、未 opens，trySetAccessible() 返回 false，而 setAccessible(true) 抛 InaccessibleObjectException。框架应把无法访问记录为可诊断的配置错误或按契约降级。首选由模块提供明确的 public getter 或序列化协议。确需深反射时，可用 opens config.internal to trusted.mapper 定向授权；部署期 --add-opens 要记录范围。

## 限制反射的输入

将外部输入的可访问字段名映射到预先允许的属性，例如把 "theme" 映射到配置接口的 theme()。不可信输入若可直接选择任意类名、方法或 private 字段，会放大开放包带来的权限。调用时单独处理找不到成员、访问未授权、目标类型不符和执行失败。为所有模块批量开放内部包不适合解决单个可信适配器的授权需求。
