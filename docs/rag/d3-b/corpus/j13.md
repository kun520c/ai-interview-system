# 迭代修改、只读视图与结构快照

适用 Java SE 21；结构修改的具体例子以 ArrayList 为准。

## 遍历期间的修改

增强 for 遍历 Iterable 时使用迭代器。循环里调用 ArrayList.remove 直接改变容器结构，绕开当前迭代器，后续遍历可能抛 ConcurrentModificationException。单线程也可能触发；某些控制流在再次检查前退出，因此不能假定必抛。ArrayList 增删元素或显式改变底层容量属于结构修改，set 只是替换现有位置元素。set 的这一点并不赋予并发安全。

## 删除与并发协调

可在单线程里对同一个迭代器先 next 再 remove，以保持迭代器状态与列表一致；Iterator.remove 是可选操作。也可用 removeIf 做单独过滤，不要从其谓词再次修改来源。共享遍历要么遵循同一同步协议，例如对 synchronizedList 返回对象加锁后整个遍历，要么选择符合业务观察语义的并发集合。捕获 fail-fast 异常不会产生互斥、可见性或稳定快照。

## 只读容器和元素生命周期

Collections.unmodifiableList(list) 返回只读视图，读操作仍转发到 backing list；若生产者后续增删或排序，视图也变化。List.copyOf(list) 返回不可修改的结构快照，源后续修改不反映到结果，且拒绝 null 元素。要保留 null 可先用独立 ArrayList 复制，再包只读视图。两种复制路径均可保留同一可变 DTO 引用，DTO 字段变化仍可观察。要固定对外响应的元素状态，可换用不可变 DTO 或复制受影响字段；从并发可变来源复制时，还需协调快照时点。
