# OpenJDK 8u HashMap 的桶、树化与扩容

实现细节固定为 OpenJDK jdk8u402-b06 的常规 putVal 路径。公开配置与容量约束按 Java SE 8 HashMap API。

## 桶定位与更新

HashMap 用桶数组组织 Node。普通 put 先取得 key 的扰动 hash，表尚未分配时初始化，以 (n - 1) & hash 定位桶。空桶直接安装节点，非空桶先检查首节点，再按普通链表或树桶路径查找或插入。匹配候选的条件包含 hash 一致与键引用相同或 equals 成立。普通 put 命中旧键会替换 value，返回旧值，size 不增加。不同键落在同一桶时可以由链表连接，在符合条件后使用红黑树节点组织桶。

## 树化与表容量

在所指定 8u 版本的普通 putVal 中，若向已经至少有 8 个节点的普通链表桶插入新节点，会尝试 treeifyBin。若 table 长度小于 MIN_TREEIFY_CAPACITY 64，则该路径优先 resize，增加桶数可能分散现有碰撞。因而仅凭桶中恰好有 8 项或重复更新同一个键无法推断已树化。扩容时原桶可按新掩码所增加的一位拆到原索引和原索引加旧容量的位置。

## 全表扩容与工程边界

默认负载因子为 0.75，可配置其他正值。通常新增映射令 size 大于 threshold 时调用 resize；上限容量有专门处理。全表阈值与局部树化判断各自触发，可以独立发生。大量独立键集中在同一桶时，先确认业务键的 equals/hashCode 和散列分布。调初始容量可以减少预期批量写入的扩容，但不能修复质量差的键。普通 HashMap 的并发写入需外部协调。
