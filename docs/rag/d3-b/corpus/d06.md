# InnoDB 行版本、快照与锁定读

## 一致性读如何选到历史版本

MySQL 8.0 的 InnoDB 采用多版本并发控制（MVCC）。聚簇记录的隐藏字段 `DB_TRX_ID` 关联最近插入或修改该记录的事务，`DB_ROLL_PTR` 指向 undo 记录。普通一致性读依据 Read View 判断版本对应的事务是否在可见边界内。当前版本不可见时，引擎可沿 undo 信息重建较早版本，直到找到可见行或确认无可见行。Read View 记录的是事务可见性范围，依赖事务 ID 和生成快照时的事务状态，也纳入当前事务对自身修改的可见性。普通一致性读通常可避开等待并发写锁。

## 两个连接看见哪些值

设设备池配额为 14，用唯一键定位同一行。连接 A 显式开事务，先做普通 SELECT，读到 14。连接 B 把配额改为 11 并提交。A 再做普通 SELECT，REPEATABLE READ 仍读 14，READ COMMITTED 读 11。普通 START TRANSACTION 下，RR 通常由第一次一致性读建立并在后续一致性读复用快照；显式 `WITH CONSISTENT SNAPSHOT` 在适用的 RR 条件下可以提前建立。RC 每次一致性读建立新快照。将测试重置后分别在两种隔离级别执行，须确保 B 提交先于 A 的第二次读取。

## 锁定读、自身写入和更新谓词

在上述 MySQL 8.0 两连接时序中，B 已提交且无其他写入时，A 两种隔离级别执行同一行的 `SELECT ... FOR UPDATE` 均读到 11 并取得排他锁。锁定读读取最新可用的版本，遇到未释放的冲突锁可能等待，锁范围也取决于索引和隔离级别。若 A 随后把这行更新为 9，两种隔离级别下 A 都可通过普通 SELECT 读到自己写入的 9。RR 中其他未被 A 修改的行仍可能来自之前的快照。面向当前库存做决策，可以把锁定读与写入置于同一事务，也可以用条件 UPDATE 把库存下界作为谓词并检查行数。先从快照算出旧值，再用无条件更新覆盖当前值，会把两种读语义混在一个决策中。
