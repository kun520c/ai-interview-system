# 面试答案提交的授权、幂等与评价提交资格

依据项目 `0c6f92afe331954f7cea37d33db688fe781cbf2c` 的 HTTP 与 Mapper 实现。答案提交从认证主体取得当前用户 ID。JWT 过滤器核验令牌并加载当前启用用户，控制器将主体 ID、路径会话 ID 与请求体传给服务。服务先校验会话归属和题目属于该会话，再按 `requestId` 查旧答案。这样其他用户即使知道请求键，也不能越过资源归属校验读取响应。重放要求旧记录的题目 ID 相同且答案正文 Java 字符串精确相等。改题或改正文都返回冲突。

## 两类唯一键与结果重放

`request_id` 的全表唯一约束保护同一请求键的重复插入，`interview_question_id` 唯一约束保护每道场内题仅有一个答案。键的 SQL 等值查询和唯一性遵循列的排序规则。例如隔离 DDL 的 `utf8mb4_unicode_ci` 不区分大小写。正文比较使用 Java 字符串语义。新提交在短事务中插入答案并条件更新题目为已回答，检查写入结果。发生唯一键竞争并回滚后按请求键重读，再按题目查找冲突归属。若旧答案已 `EVALUATED`，可以用持久化数据重建业务响应，无需它仍是当前题。若答复在网络途中丢失，客户端应复用原请求键与同一正文。已评价的重放重建结果，不承诺旧 HTTP 响应的字节完全一致。

## 取得评价资格和提交结果是两个步骤

评价发起时通过状态条件更新取得资格，并保存本次 `attemptId`。新鲜 `EVALUATING` 产生冲突。过期时可以用原请求触发受控接管，替换提交资格。写入评价和相关业务状态前检查锁定答案的状态及 `attemptId`，完成和失败更新也受本次资格约束。接管无法让旧执行者正在进行的远程调用立刻停止，但能挡住过期执行者覆盖新结果。可用 A 获得旧资格、B 过期后接管、A 迟到三步推演写入结果。SQL 的 `attempt_id` 来自单独迁移。验证真实环境时应同时检查迁移和请求键约束。
