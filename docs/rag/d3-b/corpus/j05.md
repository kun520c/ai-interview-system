# 泛型不变性和通配符的读写边界

适用 Java SE 21 的参数化子类型、通配符捕获与集合 API。

## 不变性保护写入

Integer 是 Number 的子类型，但 List<Integer> 不能赋给 List<Number>。若允许这种赋值，调用者可通过 List<Number> 写入 Double，原持有者随后却期待读到 Integer。泛型子类型关系还考虑原始类继承，例如 ArrayList<Integer> 可赋给 List<Integer>，这一关系不改变元素参数。

## 生产者和消费者的静态类型

List<? extends Number> 表示实际类型为某个未知的 Number 子类型的列表，从中读出的值可按 Number 使用。由于编译器不知道实际元素类型，不能向源加入任意非 null 的 Number、Integer 或 Double。null 是否接受还由集合契约决定。List<? super Number> 可能是 List<Number> 或 List<Object>，可加入 Number 及子类；现存元素也可能是非 Number 对象，读出时按 Object 安全。使用通配符并不决定对象实际是否可修改。

## 迁移测量样本

用 void append(List<? extends Number> readings, List<? super Number> output) 表达只读源和接收目标，遍历源后对目标 add 可保留源的参数化约束。若要使 API 对其他元素类型也适用，可声明方法类型参数 T，以 List<? extends T> 和 List<? super T> 连接两侧。Collections.copy 的参数表达同一方向，但实现按位置覆盖，要求目标列表 size 不小于源 size，不能用它替代追加。调用方还需检查目标的容量和可修改性。
