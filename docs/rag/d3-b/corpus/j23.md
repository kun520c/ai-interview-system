# CompletableFuture 的依赖、时限和取消

适用 Java SE 21 CompletableFuture、Executor 与 HttpClient。

## 依赖组合和失败边界

查询用户成功后才能查权限，可用 userFuture.thenCompose(user -> loadPermissions(user.id())) 扁平化依赖；无需用户结果的配置查询可独立启动。thenCombine 汇合两路成功值；allOf 等成员都完成，返回 CompletableFuture<Void>，某成员失败时组合异常完成，实际结果仍需从各成员读取。用户或权限失败应向上游传播。可选配置只有在合同允许时才用缺省，并暴露降级原因，避免错误地把权限失败当成授权成功。

## 选择执行器

无显式 Executor 的常规 CompletableFuture 异步工厂通常使用 ForkJoinPool.commonPool；若公共池不支持至少二级并行，则使用每任务新线程。自定义子类还可影响部分实例方法的默认执行器。无 Async 后缀的延续动作可能在触发完成的线程执行。若要包装阻塞调用，应明确受控执行器，或在虚拟线程上配合连接数及业务并发限制。独立启动不代表资源无限。

## 总时限与底层工作

聚合时用请求总时限和剩余预算控制各下游。orTimeout 使该 CompletableFuture 超时异常完成，未承诺停止底层操作；普通 CompletableFuture.cancel 的 mayInterruptIfRunning 对该类型没有中断执行的效果。Java 21 默认 HttpClient 的可取消 future 可尝试取消交换，请求也可用 HttpRequest.Builder.timeout 设置等待响应的请求超时，流式正文的后续消费要按具体 BodyHandler 和调用流程另设约束。取消发生时远端可能已经收到或执行，需按请求合同判断是否能重试。超时指标分别记录聚合等待与客户端实际完成。
