# 双端队列的方向、容量和并发

适用 Java SE 21 Deque、ArrayDeque、LinkedBlockingDeque 与 ConcurrentLinkedDeque。

## 双端操作的方向

把 Deque 用作栈时，同一端入和出，例如 push(a)、push(b)、pop() 得到 b。用于 FIFO 时，一端进、另一端出，例如 offerLast(a)、offerLast(b)、pollFirst() 得到 a。addFirst、removeFirst、getFirst 在对应插入或读取条件不满足时使用异常，offerFirst、pollFirst、peekFirst 使用布尔值或 null 表示失败或无元素。读取但保留元素使用 peek；将 null 作为任务值会模糊空队列语义，下面三种实现均不允许 null。

## 可增长缓冲和硬容量

new ArrayDeque<>(128) 只是以至少容纳相应元素数量为初始目标，它会按需要增长，offerLast 的成功并不提供 128 项上限。单线程任务暂存可用 ArrayDeque；固定容量应采用显式的容量合同，如 new LinkedBlockingDeque<>(128)。有界队列满时 offerLast 返回 false；若允许阻塞，可用带超时的 offerLast，或在明确允许无限等待且可处理 interrupt 时用 putLast。

## 共享访问

ArrayDeque 不保证线程安全。若共享它，同一把锁须保护所有访问，尤其是检查状态后执行的复合操作。只需并发双端访问且可接受无界增长时可考虑 ConcurrentLinkedDeque；需要有界并阻塞时考虑 LinkedBlockingDeque。例子是后台日志任务，队列满后要明确拒绝或延后，不能用队列初始容量代替过载策略。观察调用方等待时间与满载次数比观察构造参数更有用。
