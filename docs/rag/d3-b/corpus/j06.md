# 擦除、桥接和运行时泛型元数据

适用 JLS 与 JVMS Java SE 21。例子保持定义加载器与具体实现一致。

## 擦除与对象身份

Java 泛型主要在编译期约束赋值与调用。参数化类型擦除到对应原始类型，类型变量擦除到最左上界的擦除，无显式上界时为 Object。List<String> strings = new ArrayList<>() 与 List<Integer> integers = new ArrayList<>() 各由同一个 ArrayList 实现创建，比较 strings.getClass() == integers.getClass() 为 true。将后者改为 new LinkedList<>() 则为 false，原因是具体实现不同。List 是变量的静态接口类型，比较时必须控制实现和类身份。参数化本身不会为每个实参组合生成一份运行时类。

## 擦除后的调用与声明元数据

例如 Source<T>.read() 的擦除描述符返回 Object，TextSource 的实现可以声明 String read()。编译器可为该实现生成带 ACC_BRIDGE 的 Object read() 转发方法，以保持接口擦除后的动态分派；调用方必要时会对返回值插入转换。class 文件 Signature 属性仍可记录字段 List<String> 的声明信息，Field.getGenericType 可反射得到 String 实参，Field.getType 则得到 List。声明元数据不等于运行时实例普遍保有元素实参标签，也不能校验该列表实际包含的每一项。

## 限制与检查

不能写 new T() 或直接创建 new List<String>[10]，也不能用 read(List<String>) 和 read(List<Integer>) 做同名擦除签名的重载。Java 21 中，Object x 不能直接做 x instanceof List<String>，可以检查 x instanceof List<?>。从静态类型 List<Integer> 对 ArrayList<Integer> 做 instanceof 在可检查转换条件下合法，这只验证对象能否作为对应运行时类使用；它没有逐个检查元素的动态类型。
