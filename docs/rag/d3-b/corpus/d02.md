# MySQL 主键、可空唯一约束与外连接

## 主键与选填字段

MySQL 8.0 的 InnoDB 表可以用 `PRIMARY KEY (id)` 表示每条记录的行标识，主键的每一列都必须非空，整个键值组合必须唯一。ID 长期稳定是业务设计约定。以登记表的选填备用邮箱为例，可以将 `backup_email` 定义为允许 NULL 的列，并为完整列添加 UNIQUE。非空值如果按列的字符集和排序规则相等就会冲突，多个 NULL 可以共存。邮箱地址如何归一化、大小写规则如何处理，需要与实际业务约定一致。只索引字符串前缀会改变所比较的值域，不能替代完整列唯一约束。

## NULL、空字符串与条件判断

在 SQL 三值逻辑下，`backup_email = NULL` 的结果为 UNKNOWN，WHERE 仅保留谓词为 TRUE 的行。检查未填写应使用 `backup_email IS NULL`，MySQL 的空值安全等号 `backup_email <=> NULL` 在此也可表达相同条件。空字符串是非空值，`IS NULL` 不会匹配它。若业务把空串当作未填，可以在写入前统一转成 NULL，或者用 `backup_email IS NULL OR backup_email = ''` 处理已有数据。后者仍需留意列排序规则和字符串尾空格语义。

## 先匹配、再扩展、最后过滤

INNER JOIN 只返回满足 ON 条件的左右配对，一名会员匹配两个预约会有两行。LEFT JOIN 先按 ON 匹配右侧，左表每一行至少会产生一条输出，缺少匹配时右侧列填 NULL。要列出全部会员以及他们已确认的预约，可写 `member m LEFT JOIN booking b ON b.member_id = m.id AND b.status = 'CONFIRMED'`。也可以先用派生表筛选已确认的预约，再用 LEFT JOIN。若把等值状态判断放进 WHERE，补 NULL 行的条件为 UNKNOWN，便会被排除。MySQL 优化器也可据此将该外连接简化为内连接。

## 检查一个常见修补为什么仍丢行

准备一名没有预约的会员和一名只有待确认预约的会员。若 ON 只按会员 ID 匹配，在 WHERE 使用 `b.status = 'CONFIRMED' OR b.id IS NULL`，只有前者保留。待确认预约已经产生一条真实右行，连接阶段无需再构造补 NULL 行。将确认条件移回 ON，则两名会员都保留。检查匹配缺失时优先用右表声明非空的标识列，以区分补 NULL 和真实业务列本来可空。
