# 列表存储结构和访问成本

适用 Java SE 21 的 ArrayList 与 LinkedList，复杂度基于标准实现的访问路径。

## 定位和追加

ArrayList 以可增长数组保存元素引用，按下标访问通常为 O(1)，尾部追加摊还 O(1)，遇到扩容的单次追加可能复制已有引用。LinkedList 使用双向链接，按下标会从较近的一端走到目标，访问中段最坏需要 O(n)。用 get(i) 从头到尾扫描大型链表会反复定位，可能达到 O(n²)，用迭代器顺序走链接只需一次线性遍历。

## 中段修改的两部分成本

ArrayList 中段 add 或 remove 会移动后续引用。LinkedList 在已有有效游标且操作条件满足时，只需重新连好局部节点；如果每次给出的是下标，定位本身仍可能是线性成本。例如已用 ListIterator 顺序检查数据时，可以就地删除当前项。若主要工作是按随机下标读取，链表的局部修改成本低无法补偿频繁的定位。中段修改是否有游标决定了两种实现的比较条件。

## 选择与验证

读多、按下标查或批量尾部追加通常从 ArrayList 开始。任务需要从两端插拔时可先按 Deque 接口表达，再选适合线程和容量语义的实现。如果设计依赖 LinkedList 避免移动元素，确认调用方能保留并正确推进游标。分配开销、缓存局部性和具体容量增长比例受实现和负载影响，不能从复杂度直接推断所有实际数据规模的耗时。
