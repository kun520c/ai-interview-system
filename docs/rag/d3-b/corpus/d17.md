# DNS 递归解析、权威转介与记录缓存

以 RFC 1034、RFC 9499 和 RFC 3596 为基线。客户端应用通常通过本机 stub resolver 把查询交给递归解析器，请它给出最终答案或失败。递归解析器可从缓存应答，也可向上游转发。在无可用缓存且自行查询时，它向根 DNS 查询，获得负责顶级域的服务器转介，再向顶级域服务器查询并获得目标区域权威服务器转介，最后向负责目标区域的权威服务器请求记录。每次权威交互可以给出答案或转介，客户端看到的递归服务由解析器完成这些迭代。

## 地址、别名与缓存期限

A 记录给 IPv4 地址，AAAA 给 IPv6 地址。若名称以 CNAME 指向另一个名字，解析器继续查目标名对应的记录，目标也可能处在别的区域。TTL 表示普通缓存回答可使用该资源记录的时间上界，未过期的记录和转介缓存都可能减少上游请求。示例中权威服务给 `api.example.com` 的 A 记录 TTL 60 秒，解析器在缓存仍有效时可直接回答，剩余 TTL 随时间递减。上游无法刷新时，支持 RFC 8767 的解析器可以在规定条件下提供过期数据。地址切换期间，可对照返回记录、查询路径和 TTL 诊断新旧地址并存。

## 按连接阶段定位失败

解析取得地址后，使用 TCP 的应用仍需向目标地址与端口建立连接，HTTPS 还需执行 TLS 握手并验证服务身份。有地址但 TCP 超时可检查路由、防火墙和端口监听。TCP 成功但 TLS 主机名检查失败时，应核对应用目标名和证书标识。诊断可先使用 `dig` 查询配置的递归器并查看 TTL，再根据需要对照权威答案。`dig +trace` 从当前命令进程观察迭代路径，实际应用可能依赖递归服务、转发和本地缓存。
