# Spring JDBC 事务传播、保存点与连接占用

适用 Spring Framework 6.2.19 代理事务和支持 JDBC 保存点的命令式单数据源事务管理器。外层事务内调用另一个受管组件的 `REQUIRED` 方法时，两个逻辑作用域共享同一个物理事务。订单和必须成功的明细适合共享提交与回滚。若内层按回滚规则使共享事务成为 rollback-only，外层 `catch` 只能处理异常，提交时仍可能得到 `UnexpectedRollbackException`。回滚规则需考虑异常类型与代理调用是否成立。

## 保存点的局部回滚

`NESTED` 在已有事务下可以用同一物理事务内的保存点。可选的同库附加记录失败时，若支持保存点且内层触发回滚，可回到保存点，外层决定是否继续。内层正常完成也要等外层提交，外层随后回滚会撤销内层写入。没有外层时，`NESTED` 按类似 `REQUIRED` 的行为创建事务。应验证管理器、驱动与数据库支持，测试过程中避免引入隐式提交的 DDL。

## 独立提交需要独立资源

`REQUIRES_NEW` 挂起外层事务的资源绑定，为内层建立独立物理事务，内层可以独立提交或回滚。若要求安全审计在外层回滚后仍可见，可设计独立审计记录，并避免它依赖外层未提交的数据或等待外层已持有的锁。例如直接用独立事务插入引用尚未提交主记录的外键，可能等待外层，而外层又在等待内层返回。JDBC 外层连接仍占用池资源，内层要再取连接。按最大并发、嵌套深度、连接获取等待和查询时限评估池容量，并用独立读连接验证真实提交结果。
