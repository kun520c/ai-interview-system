# Spring MVC 请求体转换、参数校验与错误响应

适用 Spring Framework MVC 6.2.19，示例使用 Jakarta Bean Validation 3.0，控制器无类级 `@Validated`。收到 JSON 请求后，`@RequestBody` 先由 `HttpMessageConverter` 将内容转成目标对象。JSON 损坏、类型转换不成立或要求的请求体缺失，可能抛 `HttpMessageNotReadableException`。已经解析出 DTO 才能验证 DTO 约束，例如 `record Invite(@NotBlank String email) {}` 的空白邮箱。单独在请求体参数标 `@Valid`，没有触发方法校验的直接约束且没有紧随的 `BindingResult` 时，参数级 DTO 校验失败产生 `MethodArgumentNotValidException`。`@NotBlank` 表达非空白的要求，邮箱格式可再单独约束。

## 直接参数约束与级联

若同一控制器方法还有 `@RequestParam @Min(1) int page`，直接参数约束可触发 MVC 内建方法校验。方法校验覆盖同一方法内 `@Valid` 级联的嵌套约束，失败可抛 `HandlerMethodValidationException`。`@Valid` 自身用于级联验证。请求体解析仍发生在得到可验证的参数之前。该异常默认对输入错误返回 400、对返回值约束错误返回 500。类级 `@Validated` 会让方法校验走 AOP 代理路径，处理异常时要以所用路径为准。

## 可验证的对外错误合同

可在 `@RestControllerAdvice` 统一映射不可读请求体、DTO 参数约束和 MVC 方法校验的输入错误为 HTTP 400，返回稳定错误码和允许公开的字段路径与提示。返回值校验失败应按服务端错误处理。也可使用 Spring 的 `ProblemDetail` 表达结构化错误，并按 RFC 9457 约束公开细节。用三组输入测试损坏 JSON、空白邮箱、越界页码，单独断言错误类型与响应。原始被拒绝值、完整内部异常、堆栈和敏感字段不应被拼到公开提示。
