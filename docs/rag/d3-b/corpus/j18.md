# 对象可达性、内存泄漏与 JVM 取证

适用 Java SE 21 引用可达性与 JDK 21 HotSpot 的诊断命令。

## 生命周期和保留链

方法将请求详情放入长寿命类的 static Map 后，局部变量离开作用域只解除局部引用。仍可从根经类或其持有的静态字段、Map 条目到达详情对象，强可达的详情可继续保留。排查时在可比较负载下观察回收后存活对象基线，持续抬升提示保留问题；若堆转储已有异常持有链，也可直接沿引用追到 GC Roots，识别实际持有者。按生命周期删除、限制容量或按时淘汰均可，但应验证保留链和回收后基线在可比较负载中确有变化。

## 高分配、异常峰值和资源耗尽

高分配速率会带来更多收集活动，但回收后基线可能稳定。一次高内存或一次 OOM 不能区分泄漏、容量偏小和瞬时突发。先读 OutOfMemoryError 明细：Java heap space 可看堆对象和存活量；Metaspace 关注类加载器与元数据；本地资源分配失败按对应消息查线程数量或原生内存等证据。HotSpot NMT 需要事先启用，适合比较 JVM 跟踪的本地内存类别，不能覆盖任意第三方本地分配。

## 将时间线与修复验证关联

在同一时间窗记录进程和线程 CPU，用多次栈采样、JFR 或 GC 日志把应用热点和 GC 活动对齐。单次样本可能漏过短暂或间歇问题，先复用已有日志再选择 jcmd Thread.print 或 JFR。需要对象持有关系时评估 GC.heap_dump 的停顿、磁盘 I/O 和数据保密成本。修复后以最小复现或同类负载复测，按根因比较热点耗时、分配率、保留量或本地内存。只提高容量可能推迟再次耗尽，无法验证原持有关系已消失。
