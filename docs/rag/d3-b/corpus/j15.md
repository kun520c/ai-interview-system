# 并发集合的原子更新和迭代一致性

适用 Java SE 21 ConcurrentHashMap、CopyOnWriteArrayList 与 LongAdder API。

## 单键原子更新与回调

两个线程同时 get 到计数 4，各自 put(5)，只会增加一次。ConcurrentHashMap.merge(key, 1, Integer::sum) 或 compute 可把同一键的查找、计算、写入作为原子方法操作。putIfAbsent 登记已算出的对象；computeIfAbsent 缺失时才尝试求值，返回 null、抛异常或后来移除映射均可能导致后续重新计算。计算过程可能阻塞部分更新，应保持回调短且无阻塞 I/O，不在回调中修改同一张 Map 的映射。跨键不变量需要额外协调，单键更新也不能承诺远端请求只执行一次。用 computeIfAbsent 初始化 LongAdder 再 increment 时还需协调计数器的移除；并发 sum 不承诺原子快照。

## 写时复制的观察时点

高遍历、低变更的监听器列表可用 CopyOnWriteArrayList。迭代器固定创建时的成员数组，因此正在广播的一轮仍可能通知刚注销的成员。数组复制的是引用，监听器对象内部状态可以改变。修改成员数组通常要进行 O(n) 级引用复制，迭代器持有旧数组越久，旧数组和成员引用的生命周期越长。若注销必须等待所有正在处理的事件结束，需要独立的通知协议。

## 弱一致观察与精确快照

在线用户近似观测可用 ConcurrentHashMap 的弱一致遍历。遍历可与修改并行，可能看见部分后来更新，不提供全表一致时点。把一次遍历的条目复制到不可修改 Map 只固定这次看到的结果。要按单一时点审计，可在写入者共同遵循的锁下复制，或发布预先构造的不可变整体状态；是否还需复制值取决于值的可变性。
