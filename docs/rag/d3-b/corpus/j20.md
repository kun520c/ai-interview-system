# JMM 可见性、原子更新和互斥锁

适用 JLS SE 21 的 Java 内存模型和 Java SE 21 锁、原子变量 API。

## volatile 发布和读改写

对同一 volatile 字段的写与同步顺序中后续的读建立 happens-before。结合各线程程序顺序，发布者可先填充数据再写 volatile ready，读取线程观察 ready 后可看到对应发布之前的操作。数据若随后继续被并发改写，还需新的同步规则。volatile int count 的 count++ 包括读取、加一和写回；两个线程都可读到 4，分别写 5，导致丢失更新。单变量计数可用 AtomicInteger.incrementAndGet，多个字段共同满足不变量时用同一锁覆盖整个临界区。

## 监视器和可重入锁

synchronized 取得对象监视器，块正常或异常退出时自动释放。ReentrantLock 与监视器都允许同一持有者重入。同一把锁上的成功释放和后续成功获取提供相应的内存同步；失败获取没有这一保证。所有访问共享状态的路径须使用同一个锁实例。只需要简单互斥时可用 synchronized，若要限时获取则可选 ReentrantLock。

## 限时获取和释放责任

对共享容量设置最大等待时，tryLock(time, unit) 成功后进入 try 并在 finally unlock；返回 false 应明确失败、延期或降级，不能进入临界区或 unlock。InterruptedException 传播给上层，或者在无法传播且尚需保留信号时恢复标志并结束。普通 lock() 的典型形态是先调用 lock，再进入 try/finally，确保只在取得锁后执行解锁。将阻塞 I/O 移出临界区前，应确认外部步骤不需要依赖锁内状态持续不变。
