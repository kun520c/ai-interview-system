# 线程等待、通知与协作式中断

适用 Java SE 21 的监视器、等待集合和 Thread 中断契约。

## sleep 与目标监视器

Thread.sleep 暂停当前线程，但保留它已经持有的监视器。消费者持有 queueLock 后在空队列上循环 sleep，生产者若也需 queueLock 就无法入队。调用 queueLock.wait 必须已持有其监视器，等待期间释放该对象的监视器，仍保留线程持有的其他对象监视器。正常返回或抛 InterruptedException 前需重新获得该目标监视器。等待前还持有生产者需要的另一把锁时，仍可能阻塞推进。

## 谓词循环和通知

在同一个 queueLock 下保护队列状态。消费者用 while (queue.isEmpty()) queueLock.wait()，谓词成立后在锁内取出元素。虚假唤醒、超时等待返回或另一消费者先取走任务都会使已被唤醒的线程看到空队列。生产者在同一监视器内先入队再 notifyAll；等待者被通知后仍需竞争锁并重检条件。存在多个条件时，只有能证明选中任意等待者均可保证进展的协议才适合用 notify。

## 中断处理

interrupt 是协作信号，通常应由执行线程在边界结束、传播异常或清理资源。阻塞在 wait 或 sleep 时受到中断可抛 InterruptedException，并清除中断状态。若方法能抛出该异常，可让上层统一决定结束；若接口不允许传播而上层仍需观察信号，可 Thread.currentThread().interrupt() 后尽快退出。吞掉异常继续等待，可能让线程池无法按停机预算结束。
