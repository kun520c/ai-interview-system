# Spring 受管 Bean 的初始化、销毁与资源所有权

适用 Spring Framework 6.2.19 和 `jakarta.annotation`，以普通受管单例为例。容器先实例化对象，构造器依赖在创建时提供，属性或 Setter 注入在创建后完成。完成属性填充与相关回调后，`BeanPostProcessor` 可以参与初始化前后的处理。依赖就绪后的配置自检可放在 `@PostConstruct` 或 `@Bean(initMethod = "verify")`。`@PostConstruct` 由支持该注解的后处理器识别。若在不同方法同时配置注解、`InitializingBean` 与自定义初始化方法，顺序依次为 `@PostConstruct`、`afterPropertiesSet()`、自定义方法。常规初始化在目标上运行，应把需要事务等代理 advice 的业务动作放在明确的外部入口。

## 正常关闭时释放自有资源

应用上下文正常关闭时可用 `@PreDestroy` 或 `@Bean(destroyMethod = "close")` 释放单例自己创建并持有的连接池、线程或客户端。若客户端由另一个 Bean 所有，消费者不应提前关闭共享对象。容器可对 prototype 执行初始化回调，交付实例后由获取者负责资源回收。业务代码直接 `new` 且没有把实例交给容器管理时，Spring 不会自动注入属性或调用生命周期回调。程序被强制终止也不能依赖正常关闭路径完成持久化操作。

## 验证配置与释放责任

设有受管导入客户端，构造器接收连接配置，`verify()` 检查本地必填字段，`close()` 关闭自有资源。在测试上下文用记录调用次数的替身观察配置就绪后才执行检查，显式关闭上下文后观察资源恰当关闭。再直接创建同类的测试实例，显式使用其 `close()` 或使用 try-with-resources，对照两个创建者承担的职责。耗时网络探测适合有超时的就绪检查，避免把不确定的外部延迟塞进普通单例初始化。
