# JVM 运行时区域、栈帧与类元数据

适用 JVMS SE 21 的抽象运行时模型，类元数据实例以 JDK 21 HotSpot 为例。

## 线程私有执行状态与共享区域

每个 JVM 线程有自己的 pc 和 JVM Stack；如果实现使用本地方法栈，通常在线程创建时分配。线程执行 Java 方法时 pc 记录当前 JVM 指令地址，执行 native 方法时其值未定义。堆和方法区由 JVM 线程共享。规范模型中对象实例和数组从堆分配。方法区保存每个类的运行时常量池、字段和方法信息等逻辑内容，每个类或接口的运行时常量池由方法区分配。共享区域的含义与 Java 访问控制、并发同步各自独立。

## 调用栈帧中的值

每次方法调用创建栈帧，含局部变量表、操作数栈以及对当前类运行时常量池的引用。读取参数值、执行指令、处理正常返回或异常完成时通过栈帧承载相应状态。局部变量 Item item 中保存的是 reference 值，所指对象与引用值分开；对象字段也可存储 reference。递归过深可能触发 StackOverflowError，不能据此断定 Java 堆耗尽。

## 规范布局与实现布局

JVMS 用方法区定义共享职责，不要求特定内存组织。HotSpot 类元数据可从本地内存的 Metaspace 相关空间分配，不能逐项等同于方法区的所有逻辑内容。JIT 还可能通过逃逸分析和标量替换消除部分物理分配，语义仍须符合规范。排查内存压力时以具体报错、GC 和本地内存数据区分 Java 堆与类元数据资源。
