# Spring AOP 的代理调用路径与方法限制

适用 Spring Framework 6.2.19 的代理模式。Spring AOP 在容器暴露的代理入口拦截目标方法，事务、审计等 advice 可以在进入方法前后执行。JDK 动态代理实现目标接口，通过接口方法进入代理。CGLIB 类代理通过生成子类并覆盖方法拦截，`final` 类无法生成这种子类，`final`、`private` 或对子类不可见的方法无法这样拦截。Spring Framework 的通用代理选择会考虑目标是否实现接口及配置，Spring Boot 3.5.16 的 AOP 自动配置默认偏向类代理，可用 `spring.aop.proxy-target-class=false` 选择 JDK 代理。类代理的可拦截性仍需满足具体 advice 的可见性规则。

## 外部调用与同类内部调用

当其他组件通过注入的代理调用 `writeAudit()`，代理可以应用匹配的 advice。若组件调用目标的 `importAll()` 后，目标内部使用 `this.writeAudit()` 或省略 `this` 直接调用，内层调用走目标引用，未再次进入代理，内层方法的事务或审计声明不会单独生效。若外层已开启事务，内层的数据库操作仍可能参与该事务。给内层加 `REQUIRES_NEW` 也无法通过这个调用路径开启独立事务。

## 按事务职责分组件

例如把单笔审计写入移到另一个受管 Service，让导入编排组件通过注入的 Bean 调用，并在对外方法定义事务。用真实的 Spring 容器运行测试，分别记录 advice 是否命中和异常后的提交结果，避免直接 `new` 导致整条路径没有代理。如果需要在单个组件内显式控制事务范围，可以采用 `TransactionTemplate`。AspectJ weaving 对调用的处理属于另一种机制，需要单独配置和验证。
