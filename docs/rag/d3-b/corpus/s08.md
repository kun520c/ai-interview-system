# 提交后的外部副作用、持久待办与恢复

适用 Spring Framework 6.2.19 命令式事务事件与单库 InnoDB 的通用设计。`@TransactionalEventListener` 的默认阶段为 `AFTER_COMMIT`，在关联事务成功提交后执行。默认没有事务时不执行，可显式配置 `fallbackExecution`。提交后通知避免为已回滚的业务发送消息，但数据库已提交、进程尚未执行监听器时可能崩溃。内存事件随进程丢失，重启后数据库的成功记录仍存在。

## 同库原子保存业务与待办

例如订单更新后要通知外部排程服务。可在同一事务写订单和一条待发送记录，后者保存稳定操作键、必要载荷、状态、尝试次数和下次尝试时间。提交完成后由受控工作器找出待办，短事务取得执行资格，事务外发送，再用短事务独立确认送达或安排重试。若以提交后回调写确认，原事务资源可能仍可访问，但该阶段写入不会随原事务再次提交，应让确认获得自己的事务，例如通过代理入口或 `TransactionTemplate` 启动新事务。崩溃时通过待办状态和可恢复的执行资格继续处理。

## 发送成功和确认成功之间仍有故障窗口

远端明确拒绝时可按错误合同停止或安排有限重试。响应超时可能是远端已执行而本地尚未确认，应按稳定操作键查询远端结果，或在接收方承诺幂等时用同键同意图重放。接收方可用唯一键将去重记录和业务效果一起提交，发送方按总期限和有限退避恢复，超限进入对账。可测试提交后发送前崩溃，以及远端写完后响应丢失。本地事务原子覆盖订单与待办。跨系统最终效果还取决于接收方合同、键保留期和恢复策略。
