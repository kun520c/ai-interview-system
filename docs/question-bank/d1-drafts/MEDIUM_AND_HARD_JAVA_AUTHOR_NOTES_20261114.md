# D1 M12–M21、H10–H13 作者自查

2026-11-14。以下记录是题目作者的逐题自查。独立审查应另行确认技术表述、难度和与全题库的覆盖差异。

- **M12** 按 JLS 21 §4.12.4、§12.2–§12.4 检查 PORT 是编译期常量，retries 才是首次触发点。静态块只在成功初始化时执行，符号引用允许延迟解析。各点分别评首次读取、常量例外、再次实例化和两个阶段的工作。
- **M13** 按 Java 21 引用包与 Oracle 排查指南区分强可达、业务生命周期和 OOM。题面给定类仍存活及稳定负载，回答聚焦于对象保留路径、证据和修复后的复查。接受相当的分析工具。
- **M14** 按 Java 21 Lock、ReentrantLock 与 JLS §14.19 检查成功加锁的可见性、同步块退出、限时获取和中断分支。两个入口保护同一不变量，只有成功拿锁的路径需要释放。
- **M15** 按 Java 21 Object.wait 与 Thread.sleep、interrupt 检查释放目标监视器、重新持锁、虚假唤醒和中断状态。此题关注条件等待与取消，和 M14 的选锁任务不同。
- **M16** 按 Spring 6.2 官方参考检查单值候选、限定符、集合注入与单构造器。用“缺少进一步消歧信息”限定失败，接受用等价限定符表达指定实现。
- **M17** 按 Spring MVC 6.2 官方参考检查请求体读取、普通 DTO 验证和 MVC 内建方法验证三个阶段。直接方法参数约束会把同一方法的嵌套 DTO 校验纳入方法校验。题设排除类级 AOP 方法验证。
- **M18** 按 MySQL 8.0 手册检查 B-tree 列顺序、两列等值后的时间范围、索引排序和覆盖。B 的普通扫描仍可利用 user_id，不能由此获得跨 status 的时间顺序。替代路径的选择以计划为准。
- **M19** 按 MySQL 8.0 手册检查 possible_keys、key、type、rows、filtered 和 Extra 的口径。约 4,000 是过滤后估计，ANALYZE 对 SELECT 真正执行并产生实测数据。修复建议由证据决定。
- **M20** 按 Redis EXPIRE、INFO 与 7.2 版本配置核对主动/被动过期和三种内存策略。过期与淘汰计数只反映实例级累计变化，可提示原因。
- **M21** 按 Redis 持久化文档与 7.2 版本配置核对快照、增量 AOF、重写和启动选择。everysec 的约一秒是通常量级，保留存储及故障条件。接受按损失窗口和恢复时间提出不同策略。
- **H10** 按 Java 21 Class、AccessibleObject、Field 和 JLS §7.7.2 核对两具名模块的 private 实例字段场景。发现字段、exports、opens 及三种调用结果逐项可验证。
- **H11** 按 Java 21 Stream 契约核对 count 对已知大小来源可以跳过 peek、并行 forEach 的并发风险和结果收集顺序。审计与流计算独立，可给出保序循环。
- **H12** 按 Java 21 ConcurrentHashMap API 核对原子的单键方法和回调限制。computeIfAbsent 的调用约束以单次调用和键当时缺失为条件，null、异常或移除后仍可能重算。
- **H13** 按 Java 21 并发集合 API 核对迭代器捕获数组引用、可变元素与弱一致遍历。明确近似统计和单时点快照的需求差别，读取成本及写入开销有独立评分。
